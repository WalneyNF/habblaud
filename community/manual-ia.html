1. Instalação

Requer Node.js 22.12 ou superior. Na pasta do projeto, execute:

npm install
copy .env.example .env
notepad .env
npm run typecheck
npm run build
npm run start:ai

Se estiver usando outra porta, defina HABBLAUD_PORT=4750 no .env.

2. Como cadastrar

No laboratório, abra Configurações · Provedores. Escolha um cadastro existente ou informe um novo ID (exemplo: minha-ia), nome, protocolo, URL base, identificador do modelo e nome da variável da chave. Clique em Salvar configuração. As configurações sem segredos ficam em .habblaud-local/ai-providers.json.

3. Como configurar a chave

Abra o arquivo .env na raiz do projeto e inclua a variável desejada. Exemplo:

OPENAI_API_KEY=SUA_CHAVE_PRIVADA
GEMINI_API_KEY=SUA_CHAVE_PRIVADA
GROQ_API_KEY=SUA_CHAVE_PRIVADA
OPENROUTER_API_KEY=SUA_CHAVE_PRIVADA

Não é necessário preencher todas as chaves. Reinicie o servidor com npm run start:ai após alterar o .env. Nunca publique o arquivo .env nem compartilhe suas chaves.

4. Ollama

ollama serve
ollama pull qwen2.5-coder:3b
ollama list

Ollama usa a API nativa e normalmente não exige chave local. Selecione o modelo instalado e ajuste a URL se necessário.

5. OpenAI, Gemini, Groq e outros

OpenAI: https://api.openai.com/v1; Gemini: https://generativelanguage.googleapis.com/v1beta/openai; Groq: https://api.groq.com/openai/v1; OpenRouter: https://openrouter.ai/api/v1. Use o identificador de modelo válido para a sua conta. APIs compatíveis aceitam Chat Completions; outras APIs precisam de adaptador.

OpenCode é um aplicativo/CLI, não necessariamente um servidor Chat Completions. Para usá-lo aqui, é preciso disponibilizar uma ponte de API compatível. O cadastro não instala o OpenCode.

6. Testar a conexão

No cadastro de provedores, selecione o serviço e clique em Testar conexão do provedor selecionado. Para Ollama, o sistema consulta os modelos locais sem gerar tokens. Para serviços externos, confirme o aviso: o teste envia uma mensagem curta e pode consumir cota ou gerar cobrança. O diagnóstico identifica ausência de chave, erro de autorização, modelo inválido e limite de uso.

7. Segurança e privacidade

O navegador nunca recebe a chave pelo cadastro. O servidor lê a variável de ambiente e envia a chave ao endpoint escolhido. O arquivo .env não é criptografado: proteja as permissões do sistema. Não use URLs desconhecidas: um servidor malicioso pode receber sua chave e seus prompts. Provedores externos processam os textos enviados conforme suas próprias políticas. Atividades resumidas podem aparecer no escritório e na linha do tempo local. O acesso HTTP às novas rotas é limitado ao localhost.

7. Limitações

Esta etapa oferece chat e exibição de atividade. Não oferece edição automática de código, execução de comandos, streaming nem instalação automática de modelos. O histórico de conversa fica em memória e se perde no reinício.

8. Diagnóstico

Erro 401: chave inválida. Erro 404: URL ou modelo incorreto. Erro 429: limite da API. Erro 502: falha de conexão ou resposta. Se o modelo aparecer sem chave, revise o .env e reinicie o Node. Para o Ollama, confira http://127.0.0.1:11434/api/tags.
