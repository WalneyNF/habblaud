🤖 Manual: Habblaud com Ollama e Groq

Habblaud AI Community — primeira integração experimental

Adaptação: Walney Moreira Klein · walneyk@hotmail.com

Escritório · Laboratório de IA

1. Pré-requisitos

Instale Git, Node.js compatível com a exigência do projeto (22.12 ou superior), e Ollama caso queira IA local. No Windows, abra CMD ou PowerShell.

node --version
git --version
ollama --version

2. Obter seu fork

Clone seu repositório GitHub para uma pasta nova. Para contribuir, mantenha o original como upstream.

cd /d D:\xampp2\htdocs
git clone https://github.com/WalneyNF/habblaud.git habblaud-community
cd habblaud-community
git remote add upstream https://github.com/marmottajr/habblaud.git
npm install

Esta integração experimental deve estar presente na branch do fork antes de funcionar em outro computador. Fazer um fork no GitHub não transfere automaticamente alterações locais.

3. Ollama: IA totalmente local

Inicie o Ollama. Se já estiver rodando em segundo plano, não inicie outro servidor na mesma porta.

ollama serve

Em outro terminal, instale um modelo, se necessário:

ollama pull qwen2.5-coder:3b
ollama list
ollama run qwen2.5-coder:3b

Abra http://127.0.0.1:11434/api/tags e confirme a presença do modelo. O download consome espaço em disco; a execução depende de memória disponível.

4. Groq: API hospedada

Crie uma conta no Groq Console, gere uma chave de API e consulte os limites gratuitos e os modelos disponíveis. A oferta gratuita pode mudar. Nunca inclua a chave em HTML, repositórios ou capturas de tela.

Em PowerShell, configure a chave somente no terminal que iniciará o servidor:

$env:GROQ_API_KEY = 'SUA_CHAVE_PRIVADA'
$env:HABBLAUD_GROQ_MODEL = 'MODELO_DISPONIVEL_NA_SUA_CONTA'
npm run dev

No CMD:

set GROQ_API_KEY=SUA_CHAVE_PRIVADA
set HABBLAUD_GROQ_MODEL=MODELO_DISPONIVEL_NA_SUA_CONTA
npm run dev

O valor de HABBLAUD_GROQ_MODEL precisa corresponder a um modelo aceito pela API Groq. A chave fica no processo Node e não é enviada ao navegador.

5. Iniciar Habblaud

Na pasta do projeto:

npm run typecheck
npm run build
npm start

Abra http://127.0.0.1:4747/ para o escritório e http://127.0.0.1:4747/ia-lab para enviar tarefas aos modelos. Se a porta foi alterada, adapte as URLs. Reinicie o servidor após alterar variáveis de ambiente.

6. Como usar

Desative o modo demonstração no escritório. No Laboratório, escolha Ollama ou Groq, selecione o modelo e envie uma pergunta. O servidor cria um personagem associado ao modelo, registra a tarefa e exibe o estado de processamento no escritório. Nesta primeira etapa, a IA conversa: não lê nem altera arquivos, não executa comandos e não implementa projetos sozinha.

7. Diagnóstico

Ollama indisponível: confira se o serviço está ativo e se a porta 11434 responde. Modelo não instalado: execute ollama list e instale o nome correto. Groq 401: verifique a chave. Groq 404: confirme o identificador do modelo. Groq 429: limite de requisições; aguarde conforme orientação do provedor. Porta 4747 ocupada: encerre a instância antiga ou configure HABBLAUD_PORT. Agente não aparece: atualize a página do escritório, confirme que o demo está desligado e envie uma tarefa.

8. Segurança e publicação

As novas rotas aceitam apenas conexões locais. Não exponha o serviço diretamente à internet. Não faça commit de chaves. Preserve LICENSE e atribuições do autor original. Antes de publicar, execute typecheck, build e testes. Faça pull request para seu fork somente depois de verificar o diff. Para sincronizar o upstream, revise os conflitos antes de integrar atualizações.

9. Evolução planejada

Próximas etapas: perfis persistentes, histórico em disco, streaming de respostas, seleção de papéis, ferramentas de arquivos com confirmação, testes automatizados e integração mais profunda com a interface original. Essas funções ainda não fazem parte desta etapa.
