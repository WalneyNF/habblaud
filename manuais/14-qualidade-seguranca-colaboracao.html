Pirâmide de testes

Testes unitários verificam regras; integração verifica serviços/rotas; E2E verifica fluxos completos no navegador; testes manuais exploratórios cobrem usabilidade. Nenhum nível substitui os outros.

Comandos reais

npm run typecheck; npm test; npm run build; npm run i18n:check. Para testes específicos: npx vitest run server/agent-review.test.ts. Node >=22.12 conforme package.json.

Ambiente de testes

Use branch isolada, fixtures e dados fictícios. Não rode testes que escrevem arquivos em pastas de produção. Verifique se testes de permissões e symlinks funcionam igualmente no Windows e na CI Linux.

Segurança

Revise endpoints locais, autenticação, acesso remoto, paths, comandos, permissões de agentes, exposição de chaves, CSRF, XSS, limites de payload e dependências. Nunca publique relatórios com segredos.

Code review

Verifique comportamento, arquitetura, compatibilidade, segurança, testes, legibilidade, custo de manutenção e rollback. Separe problemas bloqueantes de sugestões opcionais. Exija evidências para aprovar.

Registro de decisões

Crie ADRs para mudanças importantes: contexto, alternativas, decisão, consequências e data. Isso ajuda novos mantenedores a entender por que a arquitetura foi escolhida.

Documentação contínua

Ao adicionar módulo, atualize manual e rode node scripts/generate-code-catalog.mjs. O catálogo detecta símbolos e imports por padrões textuais; não substitui revisão de arquitetura.

Checklist de release

CI verde, QA manual, segurança revisada, documentação, changelog, licença, artefatos testados, aprovação final, tag, release e procedimento de rollback.
