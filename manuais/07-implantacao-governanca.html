2. Configurar a main no GitHub

  1. Abra o repositório WalneyNF/habblaud e entre em Settings.
  2. Confira se o repositório é público ou privado e quais colaboradores têm acesso de escrita.
  3. Em Rules → Rulesets (ou Branch protection), crie uma regra direcionada à branch main.
  4. Exija Pull Request, revisão obrigatória, resolução de conversas e checks de CI bem-sucedidos.
  5. Exija revisão de CODEOWNERS, se disponível no plano/tipo de repositório. Verifique quem pode aprovar.
  6. Bloqueie force-push e exclusão da main e revise permissões de bypass.
  7. Limite quem pode integrar na main e publicar tags/releases oficiais. Não conceda acesso administrativo desnecessário.
  8. Teste a regra com uma PR de laboratório, sem modificar código de produção.
Importante: arquivos de governança não substituem regras reais do GitHub. A aprovação exclusiva do responsável depende de permissões, rulesets e ausência de bypass. Não presuma que isso está configurado.

3. Como recebe uma contribuição

O colaborador abre issue → cria fork/branch → envia Pull Request → CI verifica → mantenedores revisam → QA valida → coordenação decide o lançamento. Cada etapa deve deixar registro público quando não envolver dados sensíveis.

4. Testes e qualidade

O workflow existente em .github/workflows/ci.yml já executa instalação, typecheck, testes e build em PRs. Os testes não comprovam que todas as telas funcionam; QA deve usar a ferramenta Homologação e um ambiente descartável.

5. Distribuição profissional

Use GitHub Releases para versões estáveis e pré-lançamentos beta, com versão, notas, requisitos, limitações, hashes e instaladores somente após testes. Um ZIP da branch é código-fonte, não um instalador. Não publique chaves ou dados pessoais.

6. Comunidade e manutenção

Comece com triagem, documentação e revisão de PRs. Crie áreas de responsabilidade (IA, frontend, backend, segurança e QA) à medida que surgirem mantenedores confiáveis. Reconheça autores de contribuições. Registre decisões importantes em issues ou documentos de arquitetura.

7. Licença e atribuição

O Habblaud deriva de um projeto de Márcio Junior licenciado sob MIT. Preserve o arquivo LICENSE e os avisos de copyright. O trabalho comunitário não elimina os direitos e créditos dos autores originais. Confira licenças de dependências e conteúdo enviado por colaboradores.
