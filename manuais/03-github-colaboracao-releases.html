Local versus remoto

origin é o apelido de um remoto, normalmente seu fork. upstream costuma apontar para o projeto original. git remote -v mostra as URLs configuradas.

Fetch, pull e push

git fetch origin consulta novos commits sem integrar. git pull busca e integra a branch configurada. git push origin nome-da-branch publica commits locais. Sempre confira a branch antes de enviar.

Fork e Pull Request

Fork é uma cópia do repositório na sua conta. Um Pull Request permite comparar branches, revisar mudanças e discutir testes. Merge só deve acontecer quando aprovado.

Download ZIP versus release

Code → Download ZIP fornece um snapshot do código da branch escolhida. Releases podem incluir arquivos instaláveis, checksums e notas de versão. Um ZIP de código não garante execução sem Node.js e configuração.

Versionamento

Uma tag como v1.1.0 identifica um commit. SemVer usa MAJOR.MINOR.PATCH: incompatibilidades, recursos compatíveis e correções, respectivamente, quando o projeto adota esse padrão.

Distribuição experimental

Identifique claramente versão experimental, riscos, requisitos, roteiro de teste e como enviar feedback. Evite incluir chaves de API, .env e dados pessoais no pacote.

Exercício

No GitHub, abra a branch main e a feature/ollama-groq do Habblaud, compare os arquivos e encontre o commit 5d328c7. Não abra merge sem desejar publicar.

Pratique primeiro em uma pasta de laboratório. Antes de alterar branches, confira git status e preserve seus arquivos.
