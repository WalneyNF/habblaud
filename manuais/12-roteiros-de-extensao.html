Laboratório A: alterar tema

1. Crie branch feature/tema-oceano. 2. Inspecione community/market-themes.css e community/agent-market.html. 3. Acrescente tokens de cor para :root[data-theme="oceano"]. 4. Atualize o seletor e a função setTheme, que hoje só reconhece original e hacker. 5. Teste foco, modais, responsividade e persistência em localStorage. 6. Registre prints e abra PR.

Laboratório B: criar uma skill

1. Abra /agent-market. 2. Crie skill com ID curto, nome, descrição e instruções objetivas. 3. Vincule a um agente de teste. 4. Autorize uma pasta de laboratório sem segredos. 5. Faça leitura e análise de arquivo fictício. 6. Confirme que a skill não concede acesso ao sistema operacional.

Laboratório C: documentar endpoint

1. Leia server/index.ts e localize o handler. 2. Inspecione método HTTP, caminho, autenticação/autorização e validações. 3. Anote payload, resposta, erros e efeitos colaterais. 4. Crie testes de sucesso, entrada inválida, acesso negado e limites. 5. Atualize manual e changelog. Não publique endpoints inseguros.

Laboratório D: criar teste

1. Localize teste .test.ts relacionado. 2. Use fixture isolada, sem alterar arquivos reais. 3. Inclua caminho feliz, erro, limite, permissão e regressão. 4. Rode npx vitest run caminho/do/teste.test.ts. 5. Rode npm run typecheck e npm run build. 6. Compare com a CI antes de concluir.

Laboratório E: contribuição externa

1. Abra issue. 2. Crie fork/branch. 3. Faça mudança pequena com teste. 4. Atualize documentação. 5. Abra PR com checklist. 6. Aguarde revisão e checks. 7. Não faça merge direto na main.

Critérios de aprovação

Mudança compreensível, teste reproduzível, sem segredo, sem regressão relevante, documentação atualizada, aprovação dos revisores e autorização final para release.
