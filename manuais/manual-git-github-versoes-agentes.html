1. Entenda os conceitos

Git registra versões de arquivos no computador. GitHub hospeda esses registros online. Habblaud é a aplicação: para abri-la localmente, seu servidor Node.js precisa estar funcionando.

TermoSignificado
RepositórioProjeto controlado pelo Git.
BranchLinha de desenvolvimento independente.
CommitRegistro de alterações, como um ponto de salvamento.
PushEnvia commits locais para o GitHub.
FetchConsulta novidades remotas sem modificar a branch atual.
PullBaixa e integra novidades remotas.
Pull RequestProposta de revisão e integração de branches.
MergeIntegra alterações entre branches.
ReleasePublicação de uma versão identificada, podendo incluir instaladores.
O aviso “had recent pushes 17 minutes ago” significa que alguém enviou commits recentemente para a branch indicada. Não é erro e não significa que o site já esteja hospedado.

2. Principal e testes: qual baixar?

BranchFinalidadePara quem
mainVersão principal escolhida para distribuiçãoUsuários que preferem estabilidade, após homologação

Em um repositório acessível, visitantes podem escolher a branch e usar Code → Download ZIP. O ZIP geralmente contém o código-fonte, não um instalador pronto. Uma release com instalador precisa ser preparada separadamente.

Como liberar uma novidade?

Implementar → testar automaticamente → testar no navegador → corrigir problemas → obter sua aprovação → criar Pull Request → fazer merge na main → validar novamente → criar release.

Regra: nenhuma integração na main sem sua autorização.

3. Como usar no Windows

Abrir a pasta

cd D:\xampp2\htdocs\habblaud

Consultar o estado

git branch --show-current
git status --short
git log -5 --oneline
git remote -v

Se o Git avisar sobre dubious ownership, confirme a pasta e, para uma consulta isolada, use git -c safe.directory=D:/xampp2/htdocs/habblaud status --short.

Ver novidades sem aplicá-las

git fetch origin
git log --oneline HEAD..origin/feature/ollama-groq

Antes de usar git pull, confira a branch e preserve alterações locais. Não use git reset --hard ou git clean -fd sem compreender que podem apagar trabalho.

Iniciar e testar

npm install
npm run dev

Consulte a porta exibida no terminal. Se for 4747, abra http://127.0.0.1:4747/habblaud-studio.

Testes automatizados

npx vitest run server/agent-review.test.ts
npm run typecheck
npm run build
Checklist:

Não envie arquivos .env, senhas ou chaves de API para repositórios públicos.

4. Habblaud: IA além de chat

O objetivo é combinar conversa natural com agentes que entendam projetos, proponham soluções e trabalhem de forma supervisionada.

Sala de Conversas

Conversas individuais com agentes, histórico, perfis, contexto e seleção de provedor. É a interface para o usuário fazer perguntas e acompanhar raciocínios e propostas.

Sala de Equipe

Agentes especializados discutem tarefas, compartilham decisões e apresentam relatórios. Um agente líder pode coordenar o trabalho, sem receber poderes irrestritos.

Studio de Desenvolvimento

O agente lê arquivos autorizados, sugere correções, mostra diferenças e solicita aprovação. Leitura, conversa, edição e execução devem ter permissões separadas.

Atenção: conversas persistentes, colaboração multiagente avançada, comentários por linha, gravação supervisionada, backups e restauração são objetivos de evolução. Não devem ser anunciados como prontos sem implementação e testes.

Exemplo de fluxo

Usuário: “Analise o inventário do meu jogo”. Agente arquiteto descreve a estrutura. Agente de testes propõe casos de regressão. Code Review apresenta alterações no Monaco. O usuário aprova ou rejeita. Somente ferramentas autorizadas podem modificar arquivos.

5. Dúvidas frequentes

Quem baixa a main recebe as novidades de testes?

Não. As branches são independentes até ocorrer a integração.

O push coloca o Habblaud no ar?

Não. Ele envia código ao GitHub. Hospedagem e execução são etapas separadas.

O Pull Request modifica automaticamente a main?

Não. Ele propõe a integração, que precisa ser efetivada conforme as regras do repositório.

É possível conversar com agentes e pedir código?

Sim, essa é a direção proposta. Conversar é diferente de autorizar alterações no disco.

Como saber se uma versão é estável?

Por testes automatizados, testes manuais, revisão, documentação e aprovação antes da release — não apenas pelo nome da branch.
