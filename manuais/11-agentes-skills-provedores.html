ÍndiceQA e releases
Documentação baseada na inspeção dos arquivos reais. Alguns exercícios são propostas de modificação, não recursos já implementados. Preserve os créditos e a licença MIT original.

Duas coisas chamadas skill

No Marketplace, skill é um registro de instruções textuais, não um programa com privilégios. Já plugins/hooks sob mod/ podem integrar sistemas externos e possuem contratos próprios. Não confunda os dois.

Modelo de dados

server/agent-workbench.ts define Agent{id,name,role,personality,provider,skills[]}, Workspace{id,name,path} e Skill{id,name,description,instructions}. O armazenamento local usa .habblaud-local/agent-workbench.json por padrão, ou HABBLAUD_AI_DATA_DIR.

Skills iniciais

Há quatro skills embutidas: review (revisão), docs (documentação), tests (planejamento de testes) e security (auditoria inicial). São perfis de instrução, não executam comandos.

Cadastrar uma skill

Abra /agent-market, clique Criar skill, informe ID válido, nome, descrição e instruções. O backend valida ID com letras minúsculas e números, limita nome a 70 caracteres, descrição a 200, instruções a 3000 e catálogo a 100 skills. Teste mensagens de erro para entradas inválidas.

Cadastrar um agente

Agente exige ID, nome, papel, personalidade, provedor e lista de IDs de skills existentes. Limite de 40 agentes e até 12 skills por agente no handler atual. A existência de um ID de provedor configurado precisa ser conferida na integração; não presuma validação cruzada completa.

Workspaces autorizados

O handler exige pasta existente com caminho absoluto, bloqueia raízes e locais de sistema, limita 20 workspaces e usa realpath para reduzir fuga por symlinks. A inspeção aceita arquivos de código/texto de extensões permitidas; arquivos ocultos e nomes sensíveis são bloqueados.

API do Marketplace

GET /api/agent-workbench/catalog; POST /api/agent-workbench/agents, /skills, /workspaces, /inspect e /review. O handler restringe acesso a loopback e aplica validação de payload. A operação review verifica SHA256 do arquivo original e retorna persisted:false: não grava o código.

Provedores de IA

server/local-ai.ts inclui configurações para Ollama, OpenAI, Gemini, Groq, OpenRouter e OpenCode. As chaves são referenciadas por nomes de variáveis de ambiente, não devem ser salvas em JSON. Arquivo local padrão: .habblaud-local/ai-providers.json.

Endpoints de IA

GET /api/local-ai/providers e /models; POST /api/local-ai/providers, /test e /chat. O endpoint chat chama o provedor; valide formato de requisição, custo, consentimento de envio de código e tratamento de erro antes de oferecer a usuários.

Limites e riscos

As operações do Marketplace são locais e a leitura de arquivo pode enviar conteúdo ao provedor escolhido mediante confirmação. Nunca cadastre workspaces com dados privados para testes públicos. Evite colocar chaves de API, tokens e segredos em prompts ou logs.

Exercício guiado

Crie uma skill chamada analise_arquitetura com instruções para apontar dependências e riscos sem modificar arquivos. Cadastre um agente que a utilize e autorize somente uma pasta de laboratório. Leia um JS fictício e compare o parecer com o arquivo original.

Testes

Execute npx vitest run server/agent-review.test.ts. Confira manualmente: ID inválido, skill inexistente, workspace fora do escopo, arquivo sensível, arquivo alterado após leitura, proposta maior que 8000 caracteres e persisted:false.
